# 기술 설명

## 디스크 구조

- 원본은 DVD9(2층) ISO입니다. 1층 볼륨 끝 섹터에 UDF 앵커가 있고, 2층 PVD는 1층 볼륨 크기(L0) 위치에 있습니다.
- 게임의 IOP 리소스 모듈은 UDF로 파일을 찾습니다. 그래서 파일을 옮기거나 크기를 바꾸면 ISO9660 레코드와 UDF File Entry를 함께 고칩니다(`tools/udf.py`).
- 원래 섹터 안에 들어가는 파일은 제자리에 덮어씁니다. 넘치는 파일은 1층 끝에 붙이고 2층 전체를 그만큼 뒤로 밉니다(`tools/isobuild2.py`). 2층 내부 LBA는 상대값이라 그대로 둡니다.
- PCSX2는 이미지 가운데부터 16섹터 단위로 2층 PVD를 찾습니다. 그래서 늘리는 섹터 수는 16의 배수로 맞춥니다.

## 게임 데이터

| 형식 | 위치 | 처리 |
| --- | --- | --- |
| TERF 묶음 | `DATA/*.DAT` | 항목 표(오프셋·크기·압축 종류)를 다시 써서 항목 교체(`tools/terf.py`). 중첩 TERF도 재귀 처리 |
| LZH1(종류 5) 압축 | TERF 항목 | 해제는 게임 ELF의 디코더를 unicorn으로 실행. 다시 넣을 때도 같은 형식으로 압축(`tools/lzh.py`) |
| UIS 화면 | `UIS_*.DAT` 안 | 헤더 +8 문자열 개수, +12 표 오프셋, 레코드 (종류, 길이, 오프셋). 길어진 문자열은 블롭 끝에 붙이고 레코드만 고침(`tools/screen.py`) |
| Apt(플래시) | 온라인 메뉴 `S*.DAT` 등 | 4바이트 정렬 NUL 문자열을 가리키는 32비트 오프셋을 모두 찾아 고침(`tools/apt.py`) |
| TDB 데이터베이스 | `STDATANV.DB`, `DBTMPANV.DAT` 등 | 고정 길이 문자열 필드를 제자리 교체. 표마다 CRC-32/MPEG-2를 다시 계산(`tools/tdb.py`, `tools/content.py`) |
| 프랜차이즈 기사 | `STRYTEXT/EMAL/CPTN/HDLN.DAT` | TERF 항목 하나가 문자열 하나. `%plyr_last_name-1%` 같은 치환 기호는 그대로 둠 |
| QKL 캐시 | `FE.QKL`, `GAME.QKL` | 원본 파일 묶음의 캐시. 항목 표(DTLS) 개수를 0으로 만들어 게임이 고친 원래 파일을 읽게 함 |

## 한글 인코딩

- 쓰인 음절 1,198자에 차례로 번호를 매깁니다. i번째 음절은 2바이트 `(0xE0 + i/128, 0x80 + i%128)`로 씁니다.
- 첫 바이트가 0xE0 이상인 글자는 원래 문자열에 나오지 않습니다(라틴 문자 0xA0~0xDF는 그대로 쓸 수 있음).

## 실행파일 패치 (`tools/elfpatch.py`)

- 글자 출력 레이아웃, 폭 측정, 줄바꿈 세 루프에 분기를 넣었습니다. 첫 바이트가 0xE0 이상이면 다음 바이트와 합쳐 16비트 코드 하나로 읽습니다.
- 새 코드는 게임에서 호출하지 않는 HUFF 압축 인코더 함수 자리에 넣었습니다.
- 이름 약식 서식 `%c.%s`(이름 첫 바이트 + 성)는 한글 이름의 첫 바이트만 잘라내므로 성만 쓰는 `%.*s`로 바꿨습니다.
- 실행파일 문자열은 원래 자리에 넣습니다. 다음 문자열 직전까지(NUL 1바이트 남김) 들어가지 않으면 짧은 번역(`translation/elf_99_short.tsv`)을 씁니다.
- 원문과 번역의 서식 기호(%d, %s 등)가 다르면 넣지 않습니다(게임이 멈추는 것을 막기 위함).

## 글꼴 (`tools/kfont2.py`, `tools/fontlayer.py`)

- FNTS 폰트의 글리프 레코드는 `<HBBHHbbbB>`입니다(코드, 폭, 높이, u, v, 진행폭, x·y 오프셋). 코드 오름차순으로 정렬해야 합니다(엔진이 이진 탐색).
- 원본 텍스처는 4bpp(농도 0~15)입니다. 한글 1,198자를 그대로 넣으면 그래픽 메모리가 모자라 경기 중 화면(코인 토스·일시정지 메뉴)이 사라졌습니다.
- 그래서 4bpp 한 칸에 2비트 글리프 두 벌을 겹쳐 담습니다(하위 2비트 = 레이어 1, 상위 2비트 = 레이어 2). 글리프 레코드 11번 바이트에 레이어 번호를 둡니다.
  - 레이아웃 함수는 현재 패스의 레이어가 아닌 글리프의 사각형을 만들지 않고 펜만 전진합니다.
  - 문자열 그리기 함수는 패스 0(원래 글리프)을 그린 뒤, 쓰인 레이어마다 TEX0의 CLUT를 레이어용으로 바꿔 다시 그립니다.
  - CLUT 생성 함수는 Main/Outline/Inline CLUT의 레이어용 6벌을 더 만듭니다.
- 그래도 부팅 직후 타이틀 화면처럼 여유가 적은 곳이 있어, 메뉴용 한글 글자의 최대 높이를 11픽셀로 제한했습니다(`MAXH`). 12픽셀이면 타이틀 화면의 빨간 START가, 14픽셀이면 일시정지 메뉴 글자가, 20픽셀이면 코인 토스 메뉴가 사라집니다.

## 16:9 와이드 패치 (`tools/widescreen.py`)

- 실행파일 `.data`에 4:3(`0x3FAAAAAB`)과 16:9(`0x3FE38E39`) 비율 값이 짝으로 놓인 상수 표가 있습니다. 게임 메뉴에는 16:9 선택지가 없습니다.
- 3D 투영이 읽는 4:3 자리 6곳(가상 주소 `0x75C9B8`, `0x75C9BC`, `0x75E91C`, `0x75E924`, `0x75E930`, `0x75FB48`)을 16:9 값으로 바꿉니다.
- 2D 화면(메뉴·HUD)은 이 값을 쓰지 않아 화면 가운데 4:3 영역에 그대로 그려집니다.
- pnach 파일 이름의 CRC는 실행파일 전체를 32비트 단어로 XOR한 값입니다. 한글패치가 실행파일을 고치므로 한글판(`2DC0CCCA`)과 원본판(`93CFD46C`)의 CRC가 다릅니다. 빌드할 때마다 두 파일을 새로 만듭니다.
- 메모리 비교로 찾은 화면 비율 설정 변수(힙 영역)는 주소가 실행마다 달라 쓰지 않았습니다.
